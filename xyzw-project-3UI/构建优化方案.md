## 二、优化 1：Arco Design 按需引入 [P2 — 可选，功能移植完成后再执行]

> **注意 (2026-06-04)**：当前采用 APK528 同款全量导入方案（`import "@arco-design/web-vue/dist/arco.css"` + `ArcoResolver({ importStyle: false })`），详见 [IMPLEMENTATION-PLAN.md](xyzw-project/IMPLEMENTATION-PLAN.md)。按需引入作为可选优化项，在功能移植全部完成并验证通过后再评估是否执行。

### 问题

`main.js` 中全量引入 Arco Design：

```javascript
import ArcoVue from "@arco-design/web-vue";  // 全量引入 60+ 组件
app.use(ArcoVue);                             // 注册全部组件
```

Arco Design 全量约 2,300 KB，项目实际只用了约 20 个组件（Button, Card, Form, Input, Select, Switch, Tabs, Tag, Dropdown, Upload, Empty, Modal, Message, Avatar, Drawer, ConfigProvider, Table, Tooltip, Popconfirm, Spin）。

### 方案

项目已安装 `unplugin-vue-components` 并配置了 `ArcoResolver`（`vite.config.js` L77-87），只需：

1. 删除 `main.js` 中的全量引入：

```diff
- import ArcoVue from "@arco-design/web-vue";
- app.use(ArcoVue);
```

2. 修改 `ArcoResolver` 配置，启用样式按需导入：

```diff
  ArcoResolver({
-   importStyle: false,
+   importStyle: 'css',
  })
```

3. 删除 `main.js` 中的全量 CSS 导入：

```diff
- import "@arco-design/web-vue/dist/arco.css";
```

4. 命令式 API（`Message`、`Modal`）需确认样式是否随按需导入自动加载。若不加载，需手动补充：

```javascript
import '@arco-design/web-vue/es/message/style/css';
import '@arco-design/web-vue/es/modal/style/css';
```

### 预估效果

| 指标 | 当前 | 优化后 | 降幅 |
|------|------|--------|------|
| `index.js` 原始大小 | 4,145 KB | ~1,800 KB | **-57%** |
| `index.js` gzip 大小 | 1,128 KB | ~500 KB | **-56%** |
| 首屏加载时间（3G 网络） | ~4.5s | ~2.0s | **-56%** |
| 构建时间 | 26s | ~18s | **-31%** |
| 构建内存峰值 | ~3.5 GB | ~2.0 GB | **-43%** |

### 工作量

30 分钟

### 风险

低。需测试命令式 API（`Message.success()`、`Modal.confirm()`）的样式是否正常。

## 三、优化 2：路由级 Code-Splitting [P1]

### 问题

`GameFeatures.vue` 同步导入了 42 个子组件：

```javascript
import ClubInfo from "@/components/Club/ClubInfo.vue";
import ClubWarrank from "@/components/Club/ClubWarrank.vue";
import GoldClubList from "@/components/cards/GoldRankListPageCard.vue";
// ... 还有 39 个 import
```

用户打开"日常"tab 时，"盐场"、"排行榜"等 tab 的代码已经被加载。

### 方案

将子组件改为动态导入：

```diff
- import ClubInfo from "@/components/Club/ClubInfo.vue";
+ const ClubInfo = () => import("@/components/Club/ClubInfo.vue");
```

Vite 会自动将每个 `import()` 拆分为独立 chunk。

配合 `<Suspense>` 处理加载状态：

```html
<Suspense>
  <template #default>
    <ClubInfo v-if="activeSection === 'club'" />
  </template>
  <template #fallback>
    <a-spin />
  </template>
</Suspense>
```

### 预估效果

| 指标 | 当前 | 优化后 |
|------|------|--------|
| GameFeatures 初始加载 | 731 KB (gzip 190 KB) | ~150 KB (gzip ~40 KB) |
| 各子组件 chunk | 不存在 | 每个 10-50 KB，按需加载 |
| 首屏可交互时间 | 等待 731 KB 全部下载 | 只下载当前 tab 的代码 |

### 用户体感

| 场景 | 当前 | 优化后 |
|------|------|--------|
| 首次打开页面 | 白屏等待 190KB(gzip) | 白屏等待 40KB(gzip)，**快 4.7 倍** |
| 切换到"盐场"tab | 瞬间（已加载） | 约 0.3s 加载 30KB chunk |
| 切换到"排行榜"tab | 瞬间（已加载） | 约 0.3s 加载 35KB chunk |
| 弱网环境(3G) | 首屏 4.5s | 首屏 1.0s |
| 只看日常 tab 的总下载 | 731 KB | ~200 KB（**-73%**） |
| 访问所有 tab 的总下载 | 731 KB | 731 KB（相同） |

### 工作量

1 小时

### 风险

低。Tab 切换时有极短加载延迟（首次约 100-300ms），可通过 `<Suspense>` + 骨架屏消除体感。

## 四、优化 3：拆分 BatchDailyTasks.vue [P2]

### 问题

`BatchDailyTasks.vue` 有 **6,952 行**，是整个项目最大的单文件。构建后 213 KB（gzip 52 KB）。

### 方案

```
BatchDailyTasks.vue (6952行)
├── BatchDailyTasks.vue          → 主框架 + tab 切换逻辑 (~500行)
├── tabs/DailyTab.vue            → 日常任务
├── tabs/ClubTab.vue             → 俱乐部
├── tabs/ArenaTab.vue            → 竞技场
├── tabs/TowerTab.vue            → 爬塔
├── tabs/HangUpTab.vue           → 挂机
├── tabs/ItemTab.vue             → 道具
├── tabs/CarTab.vue              → 赛车
├── tabs/BottleTab.vue           → 瓶子
├── tabs/DreamTab.vue            → 梦境
├── tabs/StoreTab.vue            → 商店
├── tabs/LegacyTab.vue           → 遗产
├── tabs/DungeonTab.vue          → 副本
└── tabs/RecruitTab.vue          → 招募
```

共享状态通过 `provide/inject` 传递：

```javascript
// BatchDailyTasks.vue (主框架)
const batchState = reactive({ running: false, logs: [], currentTab: 'daily' });
provide('batchState', batchState);

// tabs/DailyTab.vue
const batchState = inject('batchState');
```

### 预估效果

| 指标 | 当前 | 优化后 |
|------|------|--------|
| 单文件行数 | 6,952 行 | 最大 ~500 行 |
| 构建内存峰值 | ~3.5 GB | ~2.0 GB |
| 构建时间 | 26s | ~20s |
| HMR 热更新 | 修改任何 tab 重编译 6952 行 | 只重编译变更的 tab |
| 初始加载 | 213 KB (gzip 52 KB) | ~50 KB (gzip ~12 KB) |
| 各 tab chunk | 不存在 | 每个 10-20 KB，按需加载 |

### 开发效率提升

6952 行单文件的痛点：

- IDE 卡顿（语法高亮、代码补全延迟）
- Git diff 困难（一个 tab 的改动淹没在 6952 行中）
- 代码审查困难
- HMR 慢（改一行触发整个文件重编译）
- 多人协作易产生合并冲突

拆分后每个文件 300-500 行，以上问题全部消除。

### 工作量

2-3 小时

### 风险

中。需处理 tab 间的共享状态（running、logs、addLog 等），建议用 `provide/inject` 或 Pinia store。

## 七、OOM 临时解决方案

当前通过 `NODE_OPTIONS=--max-old-space-size=4096` 解决构建 OOM。实施上述优化后，构建内存峰值降至 ~1.5 GB，可移除此参数。

建议在 `package.json` 中固化：

```json
{
  "scripts": {
    "build": "NODE_OPTIONS=--max-old-space-size=4096 vite build"
  }
}
```

或在 Cloudflare Pages 构建设置中添加环境变量 `NODE_OPTIONS=--max-old-space-size=4096`。
